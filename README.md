# KnowBase AI — 企业内部技术知识库问答

> 面向研发/运维团队的 B 端 AI 知识库问答产品，解决技术文档碎片化与检索效率低的痛点。
> 基于 RAG + CoT 架构，权限感知检索，HITL 反馈闭环，评测驱动迭代。

## 项目背景

企业内部技术文档分散在 Confluence、Wiki、飞书文档等多处，新员工排查故障时面临「搜不到 → 问同事 → 等回复」的低效循环。KnowBase AI 通过权限感知的 RAG 检索 + 大模型推理，让工程师在 30 秒内拿到准确答案。

**核心设计决策**：
- 选择 RAG 而非微调：知识更新快、成本低、幻觉可控
- 不做代码生成：边界清晰，聚焦「检索 + 推理」，代码由工程师自己写
- 权限感知检索（RBAC）：不同角色只能访问对应知识分类

## 核心功能

| 功能 | 说明 |
|------|------|
| 权限感知检索 | 基于角色（SRE/后端/前端/产品经理）过滤知识库，命中权限外内容时被动拦截 |
| 三种回答模式 | 智能排查（CoT 分步推理）/ 快速问答（直接回答）/ 仅搜索（不生成） |
| HITL 反馈闭环 | 用户纠错 → 人工审核 → 知识库补充 / Prompt 优化，三类反馈对应不同处理路径 |
| 置信度兜底 | API 异常时智能降级为本地知识库检索，保证可用性 |

## 技术架构

```
用户提问
  │
  ▼
权限过滤（RBAC）── 角色无权访问的分类被拦截
  │
  ▼
关键词检索（RAG）── 从可见知识库中召回 Top-3 相关片段
  │
  ▼
Prompt 编排 ── 智能排查：CoT 分步推理 / 快速问答：直接回答
  │
  ▼
通义千问 API（qwen-plus）
  │
  ▼
回答输出 + 反馈收集（HITL）
```

**技术栈**：
- 大模型：通义千问 qwen-plus（API 调用，不涉及模型训练）
- 检索：关键词匹配 + 权重排序（3 字关键词权重 ×3）
- 前端：HTML / CSS / JavaScript（纯前端，无需后端服务）
- 评测：Python 自动化评测脚本 + 200 题测试集

## 评测体系与优化结果

构建 200 题测试集，建立「准确率 / 幻觉率 / 路由满意度」三维评测标准，驱动 4 个版本迭代：

| 版本 | 准确率 | 幻觉率 | 路由满意度 |
|------|--------|--------|-----------|
| 基线模型（无 RAG） | 47.6% | 1.1% | 63.0% |
| + RAG 检索增强 | 54.4% | 2.1% | 64.6% |
| + RAG + CoT 推理 | **68.3%** | 3.3% | **75.1%** |

**准确率提升 +20.7pp，路由满意度提升 +12.1pp。**

优化手段：
- 知识库扩充：补充 30+ 条高频缺失知识点，覆盖 5 个分类
- Prompt 调优：CoT 分步推理模板，引导模型先提取再回答
- 检索逻辑优化：3 字关键词权重提升，过滤停用词干扰
